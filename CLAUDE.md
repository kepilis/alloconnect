# alloconnect — контекст проекта для Claude Code

Пользователь пишет по-русски (часто с телефона) — отвечать по-русски, коротко, без жаргона.
Это личное приложение пользователя и его друга: аналог Discord на двоих,
**без серверов** (P2P). Раньше называлось alocalls (до этого Duo). Текущая версия — 1.15.1.

## Принципы (обязательно соблюдать)
- Никаких своих серверов: соединение напрямую (WebRTC), сигналинг — кодами через мессенджер или через свой UDP-канал друзей.
- В логах нет IP-адресов, переписки и кодов приглашения.
- GitHub (github.com/kepilis/alloconnect) — код, файлы автообновления и релизы (по согласию пользователя).
  Ветка `main` — исходники. Ветка `updates` — файлы автообновления: app.asar, alloconnect-helper.exe,
  подписанный update.json и README. Программа читает их с raw.githubusercontent.com (`GH_REPO` в main.js)
  и ставит только после проверки подписи Ed25519 (раздел Releases — запасной путь для проверки).
- Секретный ключ подписи обновлений (`alloconnect-update-private.pem`) — только у пользователя, в репозиторий и
  в чат не попадает. Подписывает пользователь сам (см. «Выпуск версии») или указывает путь к ключу.
- В коммитах и релизах: подпись `Co-Authored-By: Claude …` можно, ссылку на сессию/чат Claude — НИКОГДА.
- README — только короткий список возможностей последней версии, нейтрально, без имён и истории.
- Совместимость протокола между версиями и платформами: коды `ALOI.`/`ALOA.`, магия пакетов `ALC1`,
  HKDF info `'alocalls friends v1'` — НЕ менять (иначе старые друзья перестанут соединяться).
- Перед выдачей сборки — автотесты двух экземпляров и перепроверка собранного архива.

## Десктоп (Windows): что есть
Electron 44 + electron-builder (zip), иконка/версия вшиваются в exe через `build/afterPack.js` (resedit).
- `main.js` — окно, трей, автозапуск, хоткеи, выбор источника стрима, логи (`%APPDATA%\alloconnect\logs`),
  IPC: друзья, UPnP, история чатов, аватарки, оверлей, приглушение, удалённое управление, саундпад.
  Переезд данных из `%APPDATA%\alocalls` при первом запуске (`migrateLegacy`).
- `renderer.js` (~3700 строк) — вся логика окна: WebRTC (одно RTCPeerConnection: трансиверы mic, video,
  saudio; data channels negotiated: 0 `duo` чат/служебное, 1 `files`, 2 `ctl` и 3 `ctlu` — управление),
  коды приглашения (SDP минифицируется, deflate-raw, base64url, ник в начале), выбор кодека
  (H264/H265/AV1/VP9/VP8 по аппаратным возможностям обоих), файлы любого размера (`FileChan`),
  чат без звонка (текст через канал друзей, файлы — отдельный data-only PeerConnection «link»),
  история (`convs`), аватарки, саундпад, приглушение (VAD → `duck-set`), рисование/указка/реакции
  поверх стрима, удалённое управление (зритель `CV`, стримящий `CS`), автопереподключение (ICE restart
  через канал друзей; начинает host, guest страхует через 20 с).
- STUN (`stun-lists.js`): основной список (Google×2, Cloudflare); если за 2.5 с нет srflx — альтернативный
  (10 серверов разных компаний) ВМЕСТО основного. Отвечающая сторона сначала делает пробу на отдельном
  PeerConnection (пересоздавать answer-соединение нельзя — ломается DTLS). Код создаётся сразу после
  первого srflx. Настройки: «сразу альтернативные», «свои STUN-серверы».
- `net-friends.js` — друзья без сервера: ID = X25519 публичный ключ, AES-256-GCM ключом пары,
  UDP напрямую (адреса: UPnP, STUN с этого порта, LAN, Tailscale, наблюдаемый), пинги, пробивка NAT,
  надёжная доставка (`sendReliable`, части по 900 символов).
- `upnp.js` — проброс порта. `overlay.html/js` — прозрачное окно поверх игры (исключено из захвата).
- `native/alloconnect-helper.cpp` (+ ViGEmClient) — помощник Windows: звук процесса/без alloconnect
  (Process Loopback), слежение за окном, приглушение программ (ISimpleAudioVolume), ввод (SendInput)
  и виртуальный геймпад Xbox (ViGEmBus). Сборка: `zig c++` (команда в README).

## Следующая задача: Android-версия
Пользователю на телефоне нужно главное: **звонить и смотреть стрим**.
План первой версии (согласован в общих чертах):
- Отдельное приложение: Capacitor (веб-часть из десктопного интерфейса, адаптированная под телефон)
  + нативный Kotlin-плагин для канала друзей (UDP + X25519 + AES-GCM, совместимый с `net-friends.js`),
  чтобы ПК видел телефон как обычного друга.
- Звонок голосом по коду и из списка друзей, чат в звонке, просмотр стрима с ПК на весь экран со звуком
  (поворот экрана), совместимость с десктопом 1.10.2 (тот же формат кодов, те же data channels).
- Входящие звонки в фоне — только опцией «быть в сети в фоне» (foreground service с постоянным
  уведомлением; пушей Google нет и не будет — это сервер). Без опции звонить может сам пользователь.
- Демонстрация экрана с телефона (MediaProjection) — вторым шагом.
- Собирать APK командной строкой (Android Studio не обязательна), подписывать своим ключом,
  отдавать пользователю файлом для установки.
- Перед большими изменениями стоит вынести общую логику соединения из `renderer.js` в модули,
  чтобы её использовали и ПК, и телефон.

## Как проверять
Две копии на одном ПК: переменная окружения `ALOCALLS_USERDATA` задаёт отдельную папку данных
(второй экземпляр тогда не блокируется). `ALOCALLS_FAKE_HELPER` — подставной помощник для тестов.
Готовые автотесты (запускались на Linux под Xvfb) — в `tests/`, описание в `tests/README.md`.

## Выпуск версии (Windows)
1. Поднять `version` в package.json (и строку «Текущая версия» здесь). Если менялся `native/alloconnect-helper.cpp` —
   пересобрать exe командой из README (zig), иначе берётся готовый `native/alloconnect-helper.exe`.
2. `npm install` (один раз), `npm run dist` → `dist/win-unpacked` и zip.
3. Подпись: `node build/sign-update.js dist/win-unpacked/resources <путь к alloconnect-update-private.pem>`
   (можно с `NOTES="что нового"`). Скрипт кладёт `update.json` в resources и печатает открытый ключ —
   он должен совпасть с `build/update-public.pem` / `UPDATE_PUBKEY` в main.js.
   Электрон-версия в manifest берётся из package-lock; если Electron обновлялся — такая версия ставится только вручную.
4. Пересобрать zip уже С `update.json`: electron-builder упаковывает zip до подписи. Содержимое `dist/win-unpacked`
   (не саму папку) запаковать в `dist/alloconnect-X.Y.Z-win.zip`.
5. Проверка: распаковать zip, сверить подпись update.json открытым ключом и sha256 файлов; извлечь app.asar
   (`npx @electron/asar extract`) и сравнить с исходниками; прогнать тесты.
6. Публикация:
   - `main`: закоммитить исходники, запушить;
   - `updates`: заменить app.asar, alloconnect-helper.exe, update.json (из `dist/win-unpacked/resources`),
     поправить версию в README ветки, запушить — с этого момента установленные копии 1.13.1+ обновятся сами;
   - релиз: `gh release create vX.Y.Z dist/alloconnect-X.Y.Z-win.zip --target main --title "alloconnect X.Y.Z" --notes "…"`.
7. Пользователю — коротко что нового.
